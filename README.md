# Task: 4 DevOps Git Version Control Project

## 1. Project Overview

This project demonstrates Git and GitHub version control best practices as part of DevOps Internship Task 4. It covers repository initialization, branching, commits, pull requests, merging, version tagging, and documentation.

## 2. Objectives

- Initialize and manage a Git repository.
- Understand the purpose of main, dev, and feature branches.
- Practice meaningful commits.
- Use GitHub Pull Requests to review and merge changes.
- Configure a .gitignore file.
- Create and manage Git tags.
- Document Git commands and workflows using Markdown.
- Understand merge conflicts and their resolution.

## 3. Tools Used

- Git
- GitHub
- Git Bash
- Visual Studio Code
- Markdown

## 4. Branching Strategy

- **main:** Contains the stable version of the project.
- **dev:** Integrates development changes before release.
- **feature/documentation:** Contains isolated documentation improvements.

## 5. Project Workflow

1. Initialize the local Git repository.
2. Create and push the main branch to GitHub.
3. Create and publish the dev branch.
4. Create a feature branch for documentation.
5. Stage and commit changes with meaningful messages.
6. Create a Pull Request from feature/documentation to dev.
7. Create a Pull Request from dev to main.
8. Create and push a version tag.
9. Verify the commit history and repository status.

## 6. Project Structure

- `README.md` — Project overview and instructions.
- `.gitignore` — Excludes unnecessary and sensitive files.
- `CHANGELOG.md` — Records project changes.
- `docs/` — Git workflow and interview documentation.
- `scripts/` — Useful Git commands.
- `screenshots/` — Evidence of completed project activities.

## 7. Useful Git Commands

```bash
git status
git branch -a
git log --oneline --graph --all
git remote -v
git tag
```

## 8. Learning Outcomes

This project provides practical experience with Git repository management, branching strategies, commits, Pull Requests, merge conflict resolution, version tagging, and project documentation.

## 9. Conclusion

The project demonstrates a structured version-control workflow using Git and GitHub, following the objectives of DevOps Internship Task 4.
